Warehouse Manager

Technical Guide & Project Documentation

3rd Semester Java Project — Team of 6

What is this project?
A desktop application built with Java Swing that manages a warehouse. It tracks products, suppliers, stock movements, and purchase orders. All data is saved locally in JSON files using Google Gson.

1. Project Overview & How to Run

Tech Stack

  • Language: Java (JDK 17+)
  • UI Framework: Java Swing
  • Data Storage: JSON files via Google Gson library
  • Build: Manual javac compilation (no Maven/Gradle needed)

How to Compile & Run

# Step 1: Compile all Java files javac -cp "lib/gson-2.10.1.jar" -d bin \ src/models/*.java src/exceptions/*.java \ src/utils/*.java src/storage/*.java \ src/services/*.java src/ui/*.java \ src/main/Main.java # Step 2: Run the application java -cp "bin;lib/gson-2.10.1.jar" main.Main

Features

  • Add, edit, delete Products with validation
  • Manage Suppliers with referential integrity checks
  • Track Stock Movements (Stock In / Stock Out)
  • Create and manage Purchase Orders (Pending → Received / Cancelled)
  • Dashboard with KPIs: total products, suppliers, low-stock alerts, inventory value
  • Reports: sort by price/quantity, vendor breakdown, low-stock filter
  • Full Audit Log of all transactions
  • All data persisted to JSON files automatically

4. Architecture & Layer Diagram

The app follows a 3-layer architecture:

  • UI Layer (top) — What the user sees. Swing panels that display data and handle clicks.
  • Service Layer (middle) — The business logic. Validates data, enforces rules, coordinates operations.
  • Storage Layer (bottom) — Reads/writes JSON files to disk.

How Data Flows

User clicks "Add Product" in ProductPanel (UI Layer) | v ProductService.addProduct() validates the data (Service Layer) | v DataManager saves to products.json (Storage Layer)

Service Dependencies

Services depend on each other in a chain:

ReportService --------+ |---> ProductService ---> DataManager PurchaseOrderService -+---> InventoryService ---> ProductService | +---> SupplierService ---> DataManager

5. OOP Relationships Explained

1. Abstraction

BaseEntity is an abstract class. It has an abstract method toTableRow() that doesn't have a body — child classes MUST provide their own version.

public abstract class BaseEntity { protected String id; protected String name; public abstract Object[] toTableRow(); // No body! Children must implement this. }

2. Inheritance

Product and Supplier both extend BaseEntity. They inherit id and name for free, and add their own specific fields.

public class Product extends BaseEntity { private String supplierId; // Product-specific private double price; // Product-specific private int quantity; // Product-specific public Product(String id, String name, ...) { super(id, name); // Calls BaseEntity's constructor } }

3. Polymorphism

Both Product and Supplier override toTableRow() differently. When you call entity.toTableRow(), Java picks the right version based on the actual object type.

4. Encapsulation

All fields are private (or protected in BaseEntity). Access is only through getter/setter methods.

5. Generic Interface

StorageService<T> is a generic interface — the T is a placeholder for any type. DataManager implements it so it can load/save any kind of data.

public interface StorageService<T> { List<T> loadFromFile(String filePath, Type type); void saveToFile(String filePath, List<T> data); }

6. Enum

OrderStatus is a Java enum with three values: PENDING, RECEIVED, CANCELLED. It models the lifecycle of a purchase order.

7. Custom Exceptions

Three custom exception classes extend Exception (checked exceptions):

  • DuplicateProductException — thrown when you try to add a product with an ID that already exists
  • ProductNotFoundException — thrown when a product lookup fails
  • InsufficientStockException — thrown when you try to remove more stock than available

Member 5 — JSON Storage & Generics Lead

Owns: StorageService.java, DataManager.java

StorageService.java

A generic interface parameterized by <T>.

public interface StorageService<T> { List<T> loadFromFile(String filePath, Type type); void saveToFile(String filePath, List<T> data); }

The T means this interface works with ANY type — products, suppliers, orders, etc.

DataManager.java

Implements StorageService<Object>. This is the class that actually reads/writes JSON files.

FieldTypePurpose

Member 6 — Main Function, UI & Integration Lead

Owns: Main.java, UITheme.java, MainFrame.java, DashboardPanel.java, ProductPanel.java, SupplierPanel.java, InventoryPanel.java, OrderPanel.java

Main.java

The entry point. Creates all services with Dependency Injection (passing dependencies through constructors) and launches the UI.

DataManager dm = new DataManager(); ProductService ps = new ProductService(dm); SupplierService ss = new SupplierService(dm, ps); ps.setSupplierService(ss); // Circular dependency resolution InventoryService is = new InventoryService(dm, ps); PurchaseOrderService pos = new PurchaseOrderService(dm, is, ps, ss); ReportService rs = new ReportService(ps, ss); SwingUtilities.invokeLater(() -> new MainFrame(...));

SwingUtilities.invokeLater() ensures the UI is created on the correct thread (Swing Thread Safety).

UITheme.java

Defines all colors, fonts, and styling constants. Contains a CustomButton inner class that overrides paintComponent() for proper rendering on Windows.

MainFrame.java

The main window. Uses a flat sidebar for navigation and CardLayout to switch between panels without opening new windows.

Panel Files (5 panels)

SupplierPanelAdd/edit/delete suppliers form + supplier table. Delete checks if products reference the supplier.
InventoryPanelStock In/Out forms with product dropdown. Shows transaction history table. Audit log popup.
